# 01 业务手册 · 念家鲜饺供应链（实习生业务入门）

> 用途：项目业务背景与领域知识。要点式，随开发补充。配套：00-速成版、03-面试知识库。

## 1. 公司背景
- 念家鲜饺：山东念家餐饮管理有限公司旗下品牌，总部山东潍坊，2022 年创立，**纯直营**约 50 家门店，现包现煮鲜饺 + 东北菜。
- 供应链模式：**总部统采统配**（集中采购、统一配送到店），门店只提要货单；葱姜蒜等鲜活走「临采报备」例外流程。
- 目标系统：门店要货 → 总部汇总 → 分拣 → 配送 → 签收 → 对账的完整闭环 + 2 个 LLM 智能体。
- 注意：网上百科/加盟网描述的是加盟模式（直配+自采、加盟商结算）；本项目按**纯直营**设计，不要混淆。

## 2. 供应链五块地图
1. **采购**：寻源 → 比价 → 下单（采购单）→ 收货验收。术语：供应商、账期。
2. **库存**：入库 → 在库 → 出库 → 盘点。术语：SKU、批次/效期、FIFO、安全库存、库存周转天数。
3. **配送**：门店要货 → 总部汇总 → 分拣 → 装车 → 签收。术语：要货单、分拣单、配送单、POD、冷链。
4. **损耗**：临期预警 → 报损 → 退货/召回。术语：损耗率、临期、批次追溯。
5. **结算**：对账 → 开票 → 付款。术语：对账单、价目表、应收/应付、内部核算。

## 3. 术语表
| 术语 | 定义 |
|---|---|
| SKU | 最小库存单元；一个可订货的品规就是一个 SKU（如「虾仁三鲜馅 5kg/袋」） |
| 批次 | 同一批进货的标识，带生产日期/保质期；追溯的最小单位 |
| 效期 | 保质期限；鲜饺馅料以小时/天计 |
| FIFO | 先进先出：效期近的先出库 |
| 安全库存 | 低于此数必须补货的阈值 |
| 库存周转天数 | 库存平均多少天卖完一轮；越小资金效率越高 |
| 损耗率 | 损耗量 ÷ 入库量；店长 KPI 之一 |
| 要货准确率 | 销量与要货量的匹配程度；要多了报损、要少了断货 |
| 要货单 | 门店向总部提的需求单（一期核心单据） |
| 分拣单 | 总部按要货汇总后生成的拣货依据 |
| 配送单 | 一车一单，司机配送依据 |
| POD | 签收凭证（电子签收） |
| 对账单 | 总部与门店（或供应商）按期核对往来账的单据 |
| 内部盈亏核算 | 直营门店不独立注册公司，但每店独立算「收入−成本=利润」 |
| KPI | 关键绩效指标：营业额、毛利、损耗率、要货准确率等 |
| 账期 | 先货后款的天数 |
| 冷链 | 全程低温的运输/仓储链路 |
| 统采统配 | 总部统一采购、统一配送 |
| SaaS | 软件即服务：按年付费租用，免部署运维 |
| 动态扩容 | 用户/门店增长时加容器副本、扩数据库，不换系统不搬数据 |

## 4. 鲜饺行业特殊性
- 保质期以小时/天计 → 批次管理是第一优先级，FIFO 必须严格。
- 多单位换算：肉按斤、面按袋、配送按件 → 数据模型要「基础单位 + 换算系数」。
- 门店现包 → 管**原料**库存而非成品库存；损耗发生在门店（报损单）。
- 日配/隔日配 → 单据频率高，系统要支持每天批量处理。

## 5. 周边系统（采购的 IT 产品）
| 产品 | 干什么 | 为什么买 | 怎么对接 |
|---|---|---|---|
| 银豹 POS | 门店收银、打流水 | 收银专业成熟，不自研 | API 推日结流水给自研系统 → 智能体的销量数据源 |
| 金蝶精斗云 | 财务做账报税 | 财务合规专业 | 自研系统推送采购/库存/结算数据生成凭证（API/导出） |
| 管家婆进销存 | 总部仓库进销存账 | 过渡期并行 | 双轨并行 2–4 周对账一致后评估替换 |

原则：自研持有业务主数据（订单/配送/智能体），第三方做专业工具，中间 API/导出对接。

## 6. 概念扫盲
### 6.1 进销存
进货、销售、库存三本台账合一的软件。仓库每进一批记入库、每配一批记出库，结存 = 入库 − 出库。示例见《台账模板-进销存Excel版.xlsx》。Excel 版只适合小规模过渡，门店多了必须上数据库系统（就是本项目）。
### 6.2 国内知名 SaaS 清单（见识用）
- POS：客如云、美团收银、银豹（本项目选银豹）
- 财务：金蝶精斗云、用友好会计、柠檬云（本项目选金蝶）
- 进销存：金蝶精斗云云进销存、智慧记、WPS 云进销存、管家婆、点可云（本项目选管家婆）
- 会员营销：有赞、微盟（本项目会员自研，二期）
### 6.3 动态扩容（实习生重点）
- 问题：门店 50 → 300 家、用户翻倍，系统怎么不崩？
- 方案：① 后端做成**无状态容器**（不把数据存进程内存），按负载加副本；② 数据库用云托管 RDS，按需升配、加只读副本；③ 静态资源走 CDN；④ 未来量级再谈分库分表。
- 对比：老单体系统靠换更大服务器（垂直扩容，有天花板）；新系统加机器即可（水平扩容）。

## 7. 门店独立盈亏核算与店长 KPI
- **独立盈亏核算**：每店收入（流水）− 成本（原料消耗、人工、房租、摊销）= 店利润。门店不是独立法人，但账必须按店分开，否则总部不知道哪家店在亏。
- **系统含义**：所有单据挂门店维度 → 报表按店出利润。
- **店长 KPI**：营业额、毛利率、损耗率、要货准确率、卫生分，挂钩奖金。
- **系统含义**：报损单、要货单、签收单数据必须能算出这些指标；要货助手的存在意义 = 帮店长提高要货准确率。
