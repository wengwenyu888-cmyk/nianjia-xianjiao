# 03 面试知识库

> 用法：每完成一个模块，把对应考点从「□ 待沉淀」改为「■ 已沉淀」并补上项目实例。面试前对着这张表过一遍。
> 格式：考点 | 一句话要点 | 状态

## 业务类
| 考点 | 一句话要点 | 状态 |
|---|---|---|
| 进销存/ERP | 进销存 = 采购+销售+库存台账；ERP 更大（含财务人力一体化） | □ |
| SaaS vs 自研 | 租用免运维 vs 数据自主可定制；本项目核心自研、周边采购 | □ |
| 直营 vs 加盟 | 直营：总部统采统配、门店内部核算；加盟：多租户隔离、结算透明 | □ |
| 供应链五块 | 采购/库存/配送/损耗/结算，单据链闭环 | □ |

## 技术类
| 考点 | 一句话要点 | 状态 |
|---|---|---|
| 前后端分离与 REST | 资源导向 URL、JSON、无状态、幂等、分页 | ■ 实例：39 端点与前端 4 页面按 §8 契约联调，分页契约 {list,total,page,page_size} 平铺 |
| FastAPI | 异步框架、Pydantic 校验、自动 OpenAPI 文档 | ■ 实例：依赖注入（get_db/get_current_user/require_permission）、统一异常处理器 |
| Vue3 | 组件化、响应式、Element Plus 中后台组件库 | ■ 实例：4 个主数据管理页（分页/表单校验/对话框） |
| 数据库选型 | MySQL 生态最成熟、SQLAlchemy 无缝；对比 PG/国产库的思路 | ■ 实例：选型过程调研过达梦/GreatSQL/TDSQL-C，最终定 MySQL 的理由 |
| SQLAlchemy ORM | 对象映射、会话管理、dialect 方言切换数据库 | ■ 实例：26 张表模型 + Mixin（审计/软删/乐观锁），三方 DDL 逐列比对 0 差异 |
| 软删除与唯一索引 | MySQL 唯一索引 NULL 不参与约束，deleted_at 必须用 NOT NULL 哨兵值 | ■ 实例：deleted_at DEFAULT '1970-01-01' 组合唯一索引，软删后可重开同编码 |
| 幂等设计 | 幂等键唯一索引兜底，重复提交返回首次结果，同键异体 40900 | ■ 实例：单据头 idempotency_key；主数据用业务编码唯一索引做幂等锚点 |
| 数据库事务 ACID | 原子性/一致性/隔离性/持久性；单据状态流转必须事务 | ■ 实例：收货/分拣/签收三处「批次结存 + 批次流水」同事务双写，失败整体回滚 |
| 索引 | 加速查询；联合索引最左前缀；避免全表扫描 | ■ 实例：26 表 33 个索引，每个都写设计理由注释 |
| 库存并发扣减 | 事务+行锁 或 乐观锁（版本号）；防超卖防负库存 | ■ 实例：分拣按 expire_at 升序 FIFO，SELECT ... FOR UPDATE 锁批次；库存不足 40900 整体回滚；收货重复提交行锁 + 状态机 40900 |
| 多单位换算 | 基础单位 + 换算系数表；展示单位与计算单位分离 | ■ 实例：qty_base(基础单位)/qty_unit(展示单位)/convert_factor；库存展示量=qty_base÷convert_factor |
| 批次与追溯 | 批次号贯穿入库→出库→签收单据链；FIFO | ■ 实例：批次号贯穿「采购收货→分拣落批次→配送→签收」；恒等式 batch_stock.qty_base = Σ batch_flow.qty_change_base 逐笔成立 |
| 单据与流水双写 | 结存表给人看、流水表给账看；两者必须同事务且恒等 | ■ 实例：batch_stock 结存 + batch_flow append-only 流水（uk_flow_source 防重复入账） |
| 分批收货与已收量 | 部分收货要跟踪已收量，前端预填必须用「剩余量」否则重复入账 | ■ 实例：purchase_order_item.received_qty_base；修复「整单量预填」缺陷 |
| 库存预警设计 | 临期要含已过期批次（否则漏报）；低库存聚合不能滤掉零结存行（否则已耗尽 SKU 漏报） | ■ 实例：/stocks/alerts 阈值集中为模块常量 |
| 数据库迁移 | 增量迁移 + 部署时自动 upgrade；生产迁移必须向后兼容一个版本 | ■ 实例：alembic 0002 加 remark 列，容器启动自动 upgrade head 并验证 |
| 双轨并行迁移 | 新旧系统并行、对账一致再切流、保留回滚 | □ |
| 动态扩容 | 无状态容器多副本、云 RDS 升配、读写分离、未来分库分表 | □ |
| LLM 薄层架构 | LLM 只生成建议/解释，账目走确定性代码，人确认生效 | □ |
| 权限 RBAC | 角色-权限-数据范围；店长只见本店数据 | ■ 实例：permission/role_permission 表 + require_permission 依赖 + user.store_id 数据范围 |
| 定时任务/异步 | 日配汇总批处理；Celery/消息队列选型 | □ |
| 缓存 Redis | 价目表、登录态、建议结果缓存；缓存一致性 | □ |
| 数据一致性 | 对账任务、差异告警、幂等重试 | □ |
| 自动化测试 | pytest + 依赖注入替换（fake service），测试不依赖真实数据库 | ■ 实例：主数据模块 38 个测试全过 |
| 安全 | JWT 鉴权、参数校验、ORM 防注入、密钥不进代码库 | ■ 实例：CORS 白名单、生产关 /docs、异常不外泄堆栈、日志脱敏 |
| API 设计 | 版本化、幂等键、限流、日志留痕 | ■ 实例：统一响应 {code,message,data}、错误码分段 4xxxx、Idempotency-Key 头 |

> 每完成一个模块：在对应行补「项目实例」（例：做完要货单模块 → 在「库存并发扣减」补：用行锁+唯一索引防重复提交）。
